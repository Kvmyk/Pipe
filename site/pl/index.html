Admin, który nie śpi, rutynę robi sam, a o ważne sprawy pyta

Pipe to agent AI, który mieszka na Twoim serwerze Linux. Gdy coś się psuje, pisze do Ciebie na Telegram, szuka przyczyny i naprawia. Rutynowe poprawki, jak restart czy zmiana w konfiguracji, robi sam, z kopią i sprawdzeniem przed i po. Zanim zrobi coś, czego nie da się cofnąć, na przykład usunie dane albo ruszy SSH, pyta Ciebie.

git clone https://github.com/Kvmyk/pipe && cd pipe
sudo bash scripts/install-server.sh --lang pl

Jak wygląda praca z Pipe

Piszesz zwykłym językiem. Agent sam dobiera komendy, czyta logi i konfigurację, a gdy czegoś nie wie, szuka w internecie. Rutynowe zmiany robi od razu i pokazuje, co zrobił; przed ważnymi pokazuje dokładną komendę z planem zabezpieczeń i czeka na Ciebie.

Co robi sam, a o co pyta

O tym decyduje klasyfikator zapisany w kodzie Pipe, a nie instrukcja dla modelu. Model nie może go przekonać ani obejść.

Sam

odczyty i rutynowe zmiany z kopią i sprawdzeniem

  • logi, procesy, dyski, konfiguracja, internet
  • restart i przeładowanie usług i kontenerów
  • edycja konfiguracji (kopia, nginx -t przed, sprawdzenie po)
  • pakiety z repozytorium systemu
  • docker compose up, git pull z origin

Po Twoim „tak”

to, czego nie da się skopiować ani cofnąć, oraz każda nieznana komenda

  • usuwanie danych, wolumenów, pakietów
  • SSH, użytkownicy, zapora, cron, usługi systemd
  • kod aplikacji, Dockerfile, docker run
  • pliki z sekretami (.env, klucze)
  • wysyłanie danych poza serwer

Nigdy

odrzucane bez względu na to, kto prosi

  • rm -rf / i jego odmiany
  • mkfs, dd, wipefs na dyskach
  • zapis do /etc/shadow i /boot
  • pobieranie i uruchamianie skryptów (curl … | sh)

Gdzie z nim rozmawiasz

Backend działa na serwerze. Klienci łączą się z nim przez tunel SSH, więc na serwerze nie trzeba otwierać żadnego portu.

TerminalKomenda pipe na Twoim komputerze (Windows, macOS, Linux). Potwierdzenia pokazują komendę i plan bezpiecznika, diagramy zapisują się jako PNG. Plik dołączasz przez @ścieżka.
Przeglądarkapipe web otwiera rozmowę obok schematu serwera, na którym widać, gdzie agent właśnie pracuje. Każda zmiana ma podgląd różnic i przycisk cofnięcia. Zrzut ekranu wklejasz do rozmowy, a mikrofon nagrywa pytanie głosem.

Co jeszcze potrafi

Pilnuje bez kosztów
Co dwie minuty sprawdza dyski, pamięć, obciążenie, kontenery i nowe porty otwarte na świat. Te sprawdzenia działają bez modelu językowego, więc nic nie kosztują.
Wie, co się zmieniło
Co godzinę zapisuje stan serwera: pakiety, obrazy kontenerów, porty, crona, konta i konfiguracje. Na pytanie „co się zmieniło od wczoraj?” odpowiada z godziną.
Monitoring bez konfiguracji
Sam znajduje domeny w konfiguracji nginx, Caddy i Traefika i pilnuje certyfikatów, odpowiedzi stron, DNS oraz świeżości backupów.
Audyt bezpieczeństwa
/audyt ocenia serwer w skali 0–100: SSH, zapora, bazy wystawione na świat, konta, aktualizacje. Do każdej uwagi daje gotową poprawkę.
Wiele serwerów
Zdalne maszyny (SSH), kontenery i klastry Kubernetes dodajesz jako cele. Pomocnicy badają je równolegle i tylko czytają.
Pamięć
Zapisuje fakty o serwerze, mapę katalogów, sprawdzone procedury i rozwiązane incydenty. Gdy problem wraca, zaczyna od tego, co pomogło poprzednio.
Rutyny i przypomnienia
„Codziennie o 7 sprawdź backupy, pisz tylko jak coś jest nie tak” zakłada zadanie, które wykonuje się samo.
Inni agenci przez MCP
Claude Code czy Cursor mogą pracować na serwerze przez Pipe. Ich zmiany też czekają na Twoją zgodę.

Instalacja

Potrzebujesz serwera z Linuksem, dostępu przez SSH i klucza API do modelu językowego. Jeśli nie masz klucza, wybierz Google Gemini: darmowy klucz wygenerujesz na aistudio.google.com/apikey.

Na serwerze

Instalator postawi Dockera (jeśli go nie ma), zapyta o dostawcę modelu i klucz, sprawdzi, czy wybrany model obsługuje narzędzia, i uruchomi Pipe.

git clone https://github.com/Kvmyk/pipe && cd pipe
sudo bash scripts/install-server.sh --lang pl
# bez Dockera: sudo bash scripts/install-server.sh --mode native --lang pl

Na swoim komputerze

Instalator klienta zapyta o adres serwera. Potem w każdym terminalu wpisujesz pipe albo pipe web.

git clone https://github.com/Kvmyk/pipe && cd pipe
bash install.sh       # Linux, macOS
.\install.ps1         # Windows (PowerShell)

Telegram

Załóż bota u @BotFather, wpisz jego token i swój identyfikator do clients/telegram/.env i uruchom instalator serwera jeszcze raz. Instrukcja krok po kroku.

Kubernetes, instalację natywną z systemd i cloud-init opisuje strona Wdrożenie w dokumentacji.

Co warto wiedzieć przed instalacją

  • W trybie Docker Pipe ma dostęp do docker.sock, czyli w praktyce uprawnienia roota. Bez pytania Pipe robi tylko rutynę z kopią (restart, przeładowanie, poprawka w konfiguracji). Usunięcie danych, dostęp, autostart i nieznane komendy czekają na Ciebie, więc czytaj, co zatwierdzasz.
  • Treść rozmowy trafia do dostawcy modelu. Klucze, hasła i tokeny z plików są ukrywane przed wysłaniem, ale logi i konfiguracja już nie. Jeśli to problem, użyj lokalnego modelu przez Ollamę.
  • Rozmowy są w pamięci procesu. Restart backendu je kasuje. Pamięć o serwerze, dziennik zmian i historia zostają na dysku.
  • Jakość diagnozy zależy od modelu. Słabszy model częściej się myli. Dlatego każda zmiana przechodzi przez kopię i weryfikację, a ważne czekają na Twoje potwierdzenie.
