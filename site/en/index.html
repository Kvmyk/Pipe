An AI agent that lives on your server

Pipe watches a Linux server, messages you on Telegram when something breaks, and helps you fix it. It reads everything but changes nothing until you say yes. Before every change it takes a backup, and afterwards it checks that everything still works.

git clone https://github.com/Kvmyk/pipe && cd pipe
sudo bash scripts/install-server.sh --lang en

Open source, MIT license · works with Gemini (free tier), OpenAI, Claude, Ollama and others · version 0.26.0

What working with Pipe looks like

You write in plain language. The agent picks the commands, reads logs and configuration, and searches the web when it doesn't know something. Before it changes anything, it shows the exact command and the safety plan.

you
shop.example.com keeps throwing 502s, find out what is going on
pipe
  • docker logs shop-app
  • tail -n 80 /var/log/nginx/error.log
  • searches the web: nginx upstream timed out 110
  • reads nginx.org: ngx_http_proxy_module
pipe
This change needs your approval
$ sed -i 's/proxy_read_timeout 60s;/proxy_read_timeout 120s;/' /etc/nginx/sites-enabled/shop.conf && systemctl reload nginx
  • backup before the change: /etc/nginx/sites-enabled/shop.conf
  • check before: nginx -t (failure = nothing runs)
  • verification after: nginx runs, sites respond as before
  • if verification fails: the backup is restored automatically
you
yes
pipe

Fixed, shop.example.com responds again. The PDF report takes about 75 seconds to generate, while nginx waited only 60 for a response (proxy_read_timeout). I raised the limit to 120 seconds. The backup is in the journal; undo it with /undo.

What it does on its own, and what it asks about

This is decided by a classifier written in Pipe's code, not by an instruction to the model. The model cannot talk its way around it.

Right away

recognised reads

  • logs, processes, disks, memory
  • state of containers and services
  • reading configuration files
  • git status, git log
  • searching the web

After your yes

anything that changes the server, and every unknown command

  • writing and editing files
  • restarting services and containers
  • installing and upgrading packages
  • git pull, docker compose up
  • reading files with secrets (.env, keys)

Never

refused no matter who asks

  • rm -rf / and its variants
  • mkfs, dd, wipefs on disks
  • writing to /etc/shadow and /boot
  • downloading and running scripts (curl … | sh)

Where you talk to it

The backend runs on the server. Clients connect to it through an SSH tunnel, so no port has to be opened on the server.

TerminalThe pipe command on your computer (Windows, macOS, Linux). Confirmations show the command and the safety plan; diagrams are saved as PNG. Attach a file with @path.
Browserpipe web opens the conversation next to a map of the server that shows where the agent is working. Every change has a diff preview and an undo button. Paste a screenshot into the conversation, or ask by voice with the microphone.
TelegramAlerts, reminders and the morning report arrive here, with an "Investigate" button on alerts. You can send a voice note, a photo or a log file (voice works out of the box with Gemini, OpenAI and Groq).

What else it does

Watching at no cost
Every two minutes it checks disks, memory, load, containers and new ports open to the internet. These checks run without a language model, so they cost nothing.
Knows what changed
Every hour it records the server state: packages, container images, ports, cron, accounts and configs. "What changed since yesterday?" gets an answer with the time.
Monitoring without setup
It finds domains in the nginx, Caddy and Traefik configuration by itself and watches certificates, site responses, DNS and backup freshness.
Security audit
/audit scores the server 0–100: SSH, firewall, databases exposed to the internet, accounts, updates. Every finding comes with a ready fix.
Many servers
Remote machines (SSH), containers and Kubernetes clusters are added as targets. Helpers investigate them in parallel and only read.
Memory
It keeps facts about the server, a map of directories, proven procedures and resolved incidents. When a problem comes back, it starts from what helped last time.
Routines and reminders
"Every day at 7 check the backups, message me only if something is wrong" sets up a task that runs by itself.
Other agents over MCP
Claude Code or Cursor can work on the server through Pipe. Their changes also wait for your approval.

Installation

You need a Linux server, SSH access and an API key for a language model. If you don't have one, pick Google Gemini and create a free key at aistudio.google.com/apikey.

On the server

The installer sets up Docker (if missing), asks for the model provider and key, checks that the chosen model supports tools, and starts Pipe.

git clone https://github.com/Kvmyk/pipe && cd pipe
sudo bash scripts/install-server.sh --lang en
# without Docker: add --mode native

On your computer

The client installer asks for the server address. After that you type pipe or pipe web in any terminal.

git clone https://github.com/Kvmyk/pipe && cd pipe
bash install.sh       # Linux, macOS
.\install.ps1         # Windows (PowerShell)

Telegram

Create a bot with @BotFather, put its token and your user id into clients/telegram/.env and run the server installer again. Step-by-step guide (in Polish).

Kubernetes, native install with systemd and cloud-init: docs/deploy.md (in Polish).

Worth knowing before you install

  • In Docker mode Pipe has access to docker.sock, which in practice means root. Your protection is the confirmation of every change, so read what you approve.
  • The conversation goes to the model provider. Keys, passwords and tokens from files are hidden before sending, but logs and configuration are not. If that is a problem, run a local model with Ollama.
  • Conversations live in process memory. A backend restart clears them. What Pipe knows about the server, the change journal and the history stay on disk.
  • Diagnosis quality depends on the model. A weaker model is wrong more often. That is why changes always go through confirmation and verification.

Details: docs/security.md (in Polish).
